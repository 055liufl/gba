# crates/

Library crates that make up the GBA core logic. The CLI binary in `apps/` depends on both.

## Key files

- **gba-core/** — Core execution engine: types, state persistence, context discovery, task presets, agent runner, and three orchestration engines (init, plan, run)
- **gba-pm/** — Prompt manager: embeds 15 MiniJinja templates at compile time, renders them with JSON context for agent queries

## Patterns

- Workspace dependencies declared in root `Cargo.toml`, referenced via `.workspace = true`
- `gba-core` depends on `gba-pm` for template rendering; `gba-pm` has no internal crate dependencies
- Engine pattern: each engine (`InitEngine`, `PlanEngine`, `RunEngine`) owns an `AgentRunner` + `PromptManager` and drives a specific workflow
- Error types use `thiserror` with domain-specific enums per crate (`GbaCoreError`, `GbaPmError`)

## Dependencies

- `gba-pm` → standalone (minijinja, serde_json, thiserror)
- `gba-core` → depends on `gba-pm`, plus claude-agent-sdk-rs, tokio, serde_yml, chrono, regex
- Both crates are consumed by `apps/gba-cli`

## Gotchas

- Templates are embedded via `include_str!` in `gba-pm/src/templates.rs` — adding a new template requires updating both the file and the static array
- `PresetKind` in gba-core hard-codes permission modes and max turns per task type; user config can only tighten, never loosen
- State serialization uses `serde_yml` (not `serde_yaml`) — field naming follows `camelCase` convention
